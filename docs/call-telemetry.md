# Call telemetry

Client implementation for [iOS issue 411](https://github.com/p-num/element-x-ios/issues/411). The four native event names and properties are preserved: `CallJoinAttempted`, `CallJoinOutcome`, `CallFailure`, `CallParticipationEnded`. Web reports `callPlatform=web`, `callImplementation=embedded`, a random per-join UUID, `dm|group` from the account's `m.direct` mapping, and this component's `VITE_APP_VERSION`. Host observations use their own attempt/source sequence and must not be counted as another successful call.

`CallLifecycle` and `CallCorrelation` supplement those events under schema version 1. Initiation is emitted immediately before `slot.join`; ringing requires a successfully sent positive-lifetime ring notification; connection/reconnection uses `RTCParticipation.state$`'s combined membership and local media connection. `connectionScope=localMedia` does not establish remote pickup, microphone audibility or two-way media. Duplicate transitions and all transitions after termination are ignored. A startup failure ends with one failed outcome and one termination; only a once-connected attempt produces `CallParticipationEnded`. Durations use the monotonic clock and `participantsMax` includes self. Embedded host version/build are explicitly `unknown` in component records; the host's own source supplies its authoritative version/build.

The source adapter handles typed SDK errors, not server text. A peer-connection timeout is a typed startup timeout; unanswered ringing is an ordinary remote end, not a Sentry failure. The current SDK has no general homeserver-join watchdog or terminal slot-close signal in `RTCParticipation.state$`; telemetry does not fabricate either or change call behavior. A reconnect records a disconnection and, on media recovery, a reconnection; only a terminal SDK failure produces a handled error. Publication errors not exposed by the public participation model remain outside this observer.

`io.letro.call_telemetry` carries only `schemaVersion=1`, an increasing widget-wide sequence starting at one, a closed `phase`, optional closed `reason`, and `componentAttemptId`. The existing `WidgetApi` transport supplies the exact widget ID and `api=fromWidget` envelope and owns request/ack addressing. This sender neither manually posts messages nor accepts arbitrary telemetry payloads. The host may acknowledge with its `hostAttemptId` and emit the contract's `attemptLink`; component event attempt IDs remain unchanged. Existing connection-state and new lifecycle messages have independent counters.

## Correlation and privacy

`ParticipationGraph` accepts only full lowercase SHA-256 digests and positive same-snapshot co-membership evidence including the local participation. Its decreasing minimum-root aliases converge after ingestion resolves all observed edges. Room identity, empty snapshots and elapsed time never create an edge. The graph is local to one attempt; it retains already-proven overlap as original group members leave, and a new attempt does not inherit an old room's graph.

The hash preimage is six length-prefixed UTF-8 fields, each prefixed by an unsigned 64-bit big-endian byte length: domain `letro-call-participation-v1`, exact room ID, normalized slot (`m.call#room` for the historical empty/ROOM aliases), exact sender, exact member ID, verified generation. A verified modern sticky `member.id` uses `per-join`; legacy state membership requires its explicit unsigned `created_ts` as `legacy:<decimal>`. The pinned JS SDK exposes `createdTs()` with a fallback to the refreshed event's timestamp, not a safe legacy generation getter. The adapter uses the public membership parser on the actual matching event obtained from room timeline/state; it never uses that fallback. If the source event, dialect or generation cannot be verified it stays unbound. No new signaling field or Matrix state is written.

Usage events and edges follow existing PostHog consent. Call boundary capture is synchronous and checks consent before handoff, avoiding an identification promise delivering a final event after logout/reset. The outbound filter removes all automatic URL/referrer/device/person properties from the six event types and drops the historical raw `callId` property from existing analytics events too. Raw room/user/member IDs are used only locally to calculate digests, never sent as properties. Hashes are pseudonymous event context, not anonymous data or immutable universal session IDs.

Sentry uses the existing error-consent switch from `af2327aad576029d72d3b1cf1774a6f99c7a2dd8`, separately from usage consent, and production builds only. Embedded crash reporting defaults off and can be dynamically revoked by the host. A separate BrowserClient with no integrations constructs handled warning events for typed unsuccessful calls. It re-projects a small typed context at the final send boundary, removing ambient users, requests, breadcrumbs, SDK logs, extra data, arbitrary contexts/tags and server messages. Grouping uses only `call-failure/cause/phase`; UUIDs never participate in fingerprints. Permission refusal, decline, abandonment and local hangup do not generate handled errors. Delivery remains best effort; revocation is checked again before send. Existing release/source-map/scrubber work (`0b964f71`, `0c3eeea7`) remains a separate operational dependency; this change does not ship that active worktree or claim deployed source maps.

## DevOps handoff: decide before deployment

No ingestion service, Grafana dashboard, DNS/TLS/ingress change or cluster dependency is deployed by this client work.

The existing client sends usage analytics through the configured PostHog project and handled diagnostics through its configured Sentry DSN. The workspace also has existing Grafana/Loki/Tempo/Prometheus infrastructure; its live routing and tenancy must be verified by its owner before choosing an integration. Start by reusing that stack and existing authenticated ingestion/routing, rather than adding a second collector solely for these clients.

| Decision                   | Smallest reuse-first option                                                                                                              | Alternatives and tradeoffs                                                                                                                                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication and routing | Existing authenticated telemetry gateway, preserving usage and error-consent channels                                                    | A dedicated gateway offers isolation but adds service ownership, credentials, deploys and on-call work. A public client key alone is not user authentication.                                                              |
| Storage and queries        | Existing Loki event storage and Grafana queries; existing Tempo only where an approved trace pipeline already exists                     | PostHog export into existing storage may reduce client changes but needs export credentials, replay/deduplication and lag monitoring. Do not turn every event into a trace.                                                |
| Retention and access       | Reuse an approved tenant, role policy and expiry policy for pseudonymous event context                                                   | A separate tenant gives stronger separation but adds retention, access and deletion workflows. Decide whether alias lifetime must cover the entire retained event window.                                                  |
| Abuse and cardinality      | Existing rate limits, payload size limits and schema validation at ingress                                                               | Per-client/per-user controls require a reviewed authenticated identity; device/attempt/session hashes must not become Prometheus labels. Closed cause/platform/version/kind metrics can be aggregated server-side.         |
| Sampling                   | Explicitly decide whether complete outcome counts or sampled diagnostics are needed                                                      | Independent edge sampling can split sessions. If sampling is necessary, define consistent inclusion and incomplete-correlation reporting before treating aggregates as complete.                                           |
| Alias resolution           | Resolve decreasing aliases transitively in the ingestion/query path before session aggregation                                           | Query-time resolution avoids a new service but may be expensive; a durable resolver speeds queries but needs ordering, idempotency, state, expiry, backfill and failure ownership. Never merge missing edges by room/time. |
| Deduplication              | `(platform, component attempt UUID, source, sequence)` for supplementary records; native attempt/event semantics for four outcome events | Host/component `attemptLink` relates two sources without counting two calls. Widget close alone must not guess local/remote attribution.                                                                                   |
| Alerting and rollout       | Existing Grafana alert routing after retained-event/query validation                                                                     | Agree alert thresholds, minimum sample size, release cohort, suppression and responder ownership; client unit tests do not prove alerts or released ingestion.                                                             |

Before approving any new topology, DevOps should record the current gateway/tenant/route, chosen reuse option, operational owner, data retention/access policy, abuse/sampling/cardinality limits and alias-resolution algorithm. A staged validation should demonstrate auth rejection, schema rejection, consent revocation, out-of-order/duplicate edge convergence, repeat calls in the same room remaining separate and cross-platform source deduplication. Only then can a reviewed dashboard and alerts be evaluated against actual released-client traffic.
